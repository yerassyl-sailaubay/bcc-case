# Проверка качества ревью

Шесть пар небольших русскоязычных спецификаций. Документы одной пары отличаются одной смысловой правкой. Метки в `labels.json` фиксируют ожидаемый вопрос. Агент не читает эти метки. Три пары используются для разработки, три другие — для оценки. Документы синтетические, составлены в рамках проекта. Испытания на них измеряют ограниченный набор ситуаций.

| Набор | Темы | Объём |
|---|---|---|
| Разработка | Границы перевода, повторная доставка, срок изменения записи | 3 пары |
| Отложенный | Возврат и единицы, роли и исключения доступа, срок кода выдачи | 3 пары |
| Отдельный | Документ организатора, замена месяца, перестановка частей с изменением ID | 3 варианта |

```sh
uv run python evals/benchmark.py development --out evaluation-runs/development
uv run python evals/benchmark.py holdout --out evaluation-runs/holdout
uv run python evals/benchmark.py organizer --out evaluation-runs/organizer-comparison
```

Однопроходная система получает тот же документ, критерии, модель и схему результата. В эксперименте holdout каждый метод проверяет каждый документ трижды. Порядок случайный. Успешные испытания сохраняются по мере завершения. Для нового релиза используйте новый выходной каталог.

В `blind/` находятся источники и обезличенные выводы. Для каждой записи рецензент отмечает в JSON по её ID четыре поля: `seed` (true/false, null для контроля), `supported_blockers`, `false_blockers`, `actionable_questions`. Вопрос считается пригодным, если ответ определяет ожидаемое поведение в приведённом сценарии. Литературные различия не считаются пропуском. Спорные и неожиданные выводы сверяются с документом. После выставления оценок выполните:

```sh
uv run python evals/score.py evaluation-runs/holdout evaluation-runs/ratings.json
```

Скрипт раскрывает принадлежность к методу, считает попадания, ложные блокеры, цитаты, время и токены. Один документ, повторённый трижды, остаётся одним независимым примером.


### Выбор модели

На ранней версии валидатора (до нормализации ролей и ссылок) обе модели получили одни и те же шесть документов разработки в однопроходном режиме. GPT‑6 Luna завершила 6 из 6, обнаружила все три внесённых дефекта и поставила блокер на двух контрольных документах. GPT‑5.4 mini завершила 1 из 6: остальные ответы исчерпали повторную попытку проверки схемы или цитат. Это измерение совместимости моделей с первоначальным валидатором. Оно не устанавливает, как GPT‑5.4 mini работала бы с финальной версией. Для итоговых испытаний выбрана GPT‑6 Luna.

Ранние прогоны выявили ошибки обработки смешанных блоков и пропущенных строк. Итоговые результаты считаются только для зафиксированной версии. После исправлений добавлена свежая резервная пара о бронировании ячейки: контроль прошёл без замечаний, противоречие ровно на границе срока обнаружено. Для обезличенных результатов использовалась модельная оценка с проверкой выводов по исходным примерам. Независимая экспертная разметка и замер времени аналитика не проводились.

### Финальный релиз · `6bee176`

Устранены пять системных дефектов ранней версии: (1) исключены шапки таблиц и шаблонные строки из счётчика требований, удалены служебные ID пакетов `B00xx` из колонки `ID в документе`; (2) пакеты извлечения увеличены до 45 блоков и распараллелены (на официальном ТЗ число вызовов API снизилось с 25 до 4, время — с 210 с до 92,9 с); (3) валидатор цитат переведён в строгий режим — неточная или выдуманная цитата отклоняется с повторной проверкой вместо тихой подмены полным блоком; (4) `arithmetic.py` расширен на падежные формы единиц, двунаправленный пересчёт и ячейки с символом валюты (`123,45 ₸`); (5) калиброваны промпты сверки и критика (устранено сглаживание конфликта статусов, устранены ложные блокеры на чистых документах) и локализована ошибка повреждённого PDF на русском языке.

| Показатель на 42 финальных прогонах (`6bee176`) | Поэтапный агент | Один проход (`--baseline`) |
|---|---:|---:|

| Официальное ТЗ: время / вызовы API / сломанные ID в реестре | **92,9 с / 4 вызова / 0** | 55,1 с / 1 вызов / 0 |

Все 42 записи финального прогона сохранены в [final-trials.json](final-trials.json). На контрольном прогоне `organizer-corrected.md` (правка одного слова «Февральский» → «Январский») конфликт месяца исчез, а число блокеров снизилось с 5 до 3 (`84,7 с`, 4 вызова, 0 ложных тревог). При перестановке Части B перед Частью A и переименовании `Ф-` → `Пункт-` (`organizer-reordered.md`, `93,0 с`) все ключевые конфликты и пропуск активной карты KZT вновь найдены с обновлёнными адресами блоков.

### Проверка арифметики · fef85b3

Все ранее пропущенные дефекты относились к одному примеру возврата. По правилу 12 345 тиын дают 123,45 ₸, а в таблице указаны 1 234,50 ₸. Обе системы теперь получают инструкцию пересчитывать числовые примеры. Поэтапный агент дополнительно получает результаты точной арифметики для пар числовых столбцов с явным равенством единиц. Только смысл исходного текста определяет, обязаны ли значения совпадать.

| Результат на прежних шести документах, три повтора | Поэтапный агент | Один проход |
|---|---:|---:|
| Найден внесённый дефект | 9 / 9 (было 7 / 9) | 9 / 9 (было 6 / 9) |
| Контроль ошибочно заблокирован | 2 / 9 (было 0 / 9) | 0 / 9 (было 0 / 9) |
| Среднее время прогона | 18,6 с | 10,2 с |

Два ложных блокера поэтапного агента касались определения подразделения и момента поступления посылки. В этих контрольных сценариях правила уже задавали ожидаемый исход. Для прежних примеров это регрессионная проверка после изучения ошибок. На трёх новых документах каждый метод обнаружил ошибочный пересчёт длительности (2,75 мин = 165 с, в примере 156 с) и принял два контроля, включая коробку и полку разной вместимости. На новых документах было по одному прогону на метод. [Все 42 результата](conversion-trials.json).

Воспроизведение новой части: `uv run python evals/benchmark.py arithmetic --out evaluation-runs/arithmetic-new`. Для повторного сравнения на прежних документах используйте команду с `holdout` и новый каталог.

После исправления чтения адресов с описанием выполнены все 36 прогонов заново. Промпты и примеры зафиксированы. Поскольку эти документы уже использовались для проверки предыдущей версии, выводы относятся к повторному сравнению на том же наборе. [Данные каждого испытания](release-trials.json).

Оба метода стабильно выявляли конфликт доступа и пропуск срока. Агент нашёл ошибку пересчёта возврата лишь в одном из трёх повторов; один проход пропустил её во всех трёх. На исходном ТЗ пропущен конфликт месячного ограничения push с повторным достижением после смены порога. В исправленной копии агент его обнаружил. Это наблюдаемая нестабильность.

В отчёте по исходному ТЗ все 90 блоков получили классификацию. После замены месяца исчез соответствующий конфликт, а проблема HTTP-ответа при ошибке суммы сохранилась. При перестановке частей и переименовании идентификаторов конфликт месяца снова найден с новыми ссылками.

### Предыдущий отложенный прогон

Один и тот же GPT‑6 Luna, версия агента `f776610`. По 18 завершённых прогонов на метод: шесть документов, три повтора. [Отдельные результаты и оценки](trials.json).

| Показатель | Поэтапный агент | Один проход |
|---|---:|---:|

| Дефект найден во всех трёх повторах | 2 / 3 | 2 / 3 |

На этих коротких документах один проход дал ту же полноту и меньше ложных блокеров. Наиболее трудный случай для обоих методов — арифметическая ошибка в примере возврата. Агент ошибочно заблокировал два контрольных прогона, запросив механизм определения подразделения заявки и различие между фактическим и зарегистрированным поступлением посылки. Для приведённых сценариев исходные правила уже задавали ожидаемый результат. Верность цитаты не гарантирует верной оценки критичности.

Последующая правка обработки больших документов переводит адреса пакетов в локальную нумерацию. Для шести коротких документов всё содержимое помещается в первый пакет, поэтому входные адреса и инструкции те же.

Дополнительно обе резервные спецификации прошли через настоящий API как текстовые PDF. На чистом PDF замечаний не было. На PDF с конфликтом появился блокер для подтверждения ровно в момент истечения срока. Такие же результаты получены на их Markdown-версиях. Это две короткие спецификации.
